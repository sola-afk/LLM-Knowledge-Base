# Alloy

## Overview
Identity and fraud prevention platform used by ~500 banks and fintechs. Alloy's differentiator is orchestration — it unifies signals from multiple KYB data providers into a single API for consistent decisioning from onboarding through the full customer lifecycle.

## KYB Capabilities
- **Company verification**: Aggregates data from multiple verification providers
- **UBO identification**: Through integrated data sources
- **Sanctions/PEP screening**: AML screening via aggregated providers
- **Continuous KYB**: Perpetual monitoring — not just point-in-time verification
- **Multi-provider orchestration**: Combines multiple data sources for best coverage
- **Lifecycle decisioning**: From onboarding through ongoing relationship

## Developer Features
- **API**: Single unified API aggregating multiple providers
- **Codeless implementation**: No-code tools for quick deployment
- **Central console**: Consolidated data sources and verification services
- **Rapid reconfiguration**: Respond to fraud patterns quickly without code changes

## Jurisdictional Coverage
- Coverage depends on underlying data providers
- Primarily strong in US market (banking/fintech focus)
- Global coverage through provider aggregation

## Pricing
- No published rates
- Negotiated pricing — flexible for large buyers
- Opacity makes comparison difficult

## Relevance to Kota
Orchestration approach is interesting — [[Kota]] could combine best-of-breed providers through Alloy rather than picking a single vendor. Continuous KYB monitoring aligns with ongoing monitoring requirements. However, Alloy's strongest market is US banking/fintech — EU/EEA coverage needs careful evaluation. No-code tools help but pricing opacity is a disadvantage. ~500 bank/fintech customers indicates maturity.
